Next.js Interview Questions

25 questions on rendering, routing, Server Components, data fetching, caching, optimization, and deployment.

Q1. What is Next.js?

Next.js is a React framework for building full-stack web applications. It adds file-system routing, server rendering, static generation, Server Components, route handlers, image and font optimization, code splitting, and production build tooling around React.

Q2. What is the difference between React and Next.js?
ReactNext.js
A library for building component-based user interfacesA framework built on React for complete applications
Does not prescribe routing or deploymentProvides routing, server features, build tooling, and deployment options
Rendering architecture depends on the chosen setupSupports static, dynamic server, streamed, and client rendering
Q3. What are the main features of Next.js?

Important features include file-system routing, nested layouts, React Server Components, static and dynamic rendering, streaming with Suspense, route handlers, Server Functions, automatic code splitting, optimized images and fonts, metadata APIs, middleware-style request interception, and multiple deployment targets.

Q4. What is file-system routing?

Routes are created from folders and special files. In the App Router, a page.js file exposes a route and layout.js wraps pages below its segment.

app/
├── page.js                 → /
├── about/page.js           → /about
└── blog/[slug]/page.js     → /blog/:slug
Q5. What is the difference between the App Router and Pages Router?

The App Router uses the app directory and supports Server Components, nested layouts, streaming, and colocated loading and error UI. The older Pages Router uses the pages directory and APIs such as getStaticProps and getServerSideProps. Both are supported, but new applications generally use the App Router.

Q6. What are static, dynamic server, and client rendering?

Static rendering creates reusable output ahead of requests. Dynamic rendering produces output at request time using current data. Client rendering runs component logic in the browser after JavaScript loads. A Next.js route can combine server-rendered HTML with interactive Client Components.

Q7. What is Server-Side Rendering (SSR)?

SSR generates HTML on the server for a request. It is useful when content must be current or depends on request data such as cookies. It can improve the initial content and SEO, but adds server work and may require caching to handle high traffic efficiently.

Q8. What are Static Site Generation (SSG) and Incremental Static Regeneration (ISR)?

SSG creates route output before users request it, making it fast to serve and cache. ISR allows cached static content to be revalidated after deployment instead of rebuilding the entire site. Use these for content that can be shared across users and tolerate controlled staleness.

Q9. What are React Server Components in Next.js?

Pages and layouts in the App Router are Server Components by default. They can fetch from databases and use server-only secrets, and their component code is not added to the client JavaScript bundle. They cannot use browser APIs, event handlers, or stateful hooks such as useState.

Q10. When do you need "use client"?

Add "use client" at a module boundary when a component needs state, effects, event handlers, custom client hooks, or browser APIs. Everything imported below that boundary joins the client bundle, so keep the boundary as small and deep in the component tree as practical.

"use client";

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
Q11. What is hydration?

Hydration is React attaching event handlers and client behavior to server-generated HTML. Server Components themselves are not hydrated; Client Components are. A hydration mismatch occurs when the initial client render produces different markup from the server, often because rendering uses time, randomness, or browser-only values inconsistently.

Q12. What are layouts and templates?

Both wrap child routes. A layout.js persists across navigation and preserves its state and DOM. A template.js receives a new instance when its segment changes, so state resets and effects rerun. Layouts suit navigation and shared shells; templates suit transitions or UI that must reset.

Q13. How do loading and error files work in the App Router?

loading.js provides instant fallback UI and automatically wraps the route segment in Suspense. error.js is a Client Component that acts as an error boundary for a segment and can expose a retry action. not-found.js renders missing-resource UI, commonly triggered with notFound().

Q14. How is data fetched in the App Router?

Server Components can be asynchronous and call fetch, an ORM, or a database client directly. Fetch data near the component that needs it and use parallel requests where possible. Client-side data that updates frequently can use libraries such as SWR or TanStack Query.

export default async function Page() {
  const response = await fetch("https://api.example.com/posts");
  const posts = await response.json();
  return <PostList posts={posts} />;
}
Q15. What are getStaticProps, getServerSideProps, and getStaticPaths?

These are Pages Router APIs. getStaticProps supplies build-time data, getServerSideProps runs for each request, and getStaticPaths selects dynamic paths to pre-render. App Router projects instead fetch in Server Components and use APIs such as generateStaticParams and revalidation controls.

Q16. How do caching and revalidation work?

Caching stores data or rendered output so work can be reused. Revalidation refreshes cached content by time or on demand. Choose caching intentionally: personalized request data should be dynamic, while shared product or article data may be cached and invalidated after a mutation.

Q17. What are Route Handlers?

A route.js file in the App Router defines HTTP handlers using the Web Request and Response APIs. It can implement methods such as GET, POST, and DELETE.

// app/api/users/route.js
export async function GET() {
  const users = await db.user.findMany();
  return Response.json(users);
}

Server Components should usually access the data source directly rather than calling an internal Route Handler and adding an unnecessary HTTP round trip.

Q18. What are Server Functions and Server Actions?

A Server Function is an asynchronous function marked with "use server". When passed to a Client Component or form action, it is commonly called a Server Action. They are primarily useful for mutations such as form submissions; input must still be validated and every action must perform authentication and authorization.

Q19. How do dynamic routes and navigation work?

A folder such as [slug] creates a dynamic segment, [...slug] creates a catch-all, and [[...slug]] creates an optional catch-all. Use <Link> for normal navigation because it enables client-side transitions and prefetching. App Router client code can use hooks from next/navigation.

Q20. What are redirects, rewrites, and request interception?

A redirect sends the browser to a different URL. A rewrite serves content from another destination while preserving the visible URL. Request interception can run before matching routes to redirect, rewrite, or modify headers and cookies; keep it lightweight and always enforce authorization again near the data or action.

Q21. How do environment variables work?

Server code reads variables through process.env. Variables prefixed with NEXT_PUBLIC_ may be bundled into browser code and therefore must never contain secrets. Keep credentials in uncommitted environment files or the deployment platform's secret store, and access them only in server-only modules.

Q22. How do the Image component and other built-in optimizations help?

next/image can size images responsively, lazy-load them, and serve efficient formats. next/font self-hosts and optimizes fonts. Next.js also performs route-based code splitting and supports dynamic imports. Correct image dimensions help prevent layout shift.

Q23. How should authentication and authorization be implemented?

Use a trusted authentication library or a carefully designed server session. Prefer secure, HTTP-only, same-site cookies for browser sessions. Check authorization close to every protected database query, Route Handler, and Server Action; hiding UI or redirecting in request interception is not sufficient security by itself.

Q24. How can you improve Next.js performance?

Keep Client Component boundaries small, fetch on the server where appropriate, avoid sequential data waterfalls, stream slow sections with Suspense, cache shared work, optimize images and fonts, dynamically import heavy client code, use Link navigation, analyze bundles, and measure real performance rather than assuming every server-rendered route is fast.

Q25. How can a Next.js application be deployed?

It can run on a managed Next.js platform, as a Node.js server, in a Docker container, or as a static export when the application needs no runtime server features. A production pipeline should run linting, type checks, tests, and next build, then deploy an immutable artifact with environment configuration supplied at the correct runtime or build stage.

Static export note: configure output: "export" in next.config.js; the older next export command is no longer the preferred setup.
