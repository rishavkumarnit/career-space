Operating Systems Fundamentals

Q1. What is an operating system, and what are its main responsibilities?

An operating system (OS) is the software layer between applications and computer hardware. It provides a safe, consistent environment in which programs can run.

Its main responsibilities include process and CPU scheduling, memory management, file-system management, device and I/O management, security and access control, networking, and providing system calls through which applications request kernel services.

Q2. What is the difference between a program, a process, and a thread?
TermMeaning
ProgramPassive instructions stored on disk, such as an executable file.
ProcessA running instance of a program with its own virtual address space and resources.
ThreadA unit of execution inside a process. Threads share the process's code, heap, and open files, but each has its own stack and registers.

Creating and switching threads is generally cheaper than doing the same with processes, but shared memory also means threads require careful synchronization.

Q3. What is a context switch?

A context switch occurs when the CPU stops executing one process or thread and starts another. The OS saves the current execution state—such as registers, program counter, and stack pointer—and restores the next task's state.

Context switching enables multitasking but adds overhead because saving state, running the scheduler, restoring state, and disrupting CPU caches do not perform application work. Excessive switching can therefore reduce throughput.

Q4. What are the common process states?

The common states are new, ready, running, waiting/blocked, and terminated. A ready process is waiting for CPU time, whereas a blocked process is waiting for an event such as disk I/O, a network response, or a lock.

Some operating systems also use suspended-ready and suspended-blocked states when a process is temporarily moved out of main memory.

Q5. What is CPU scheduling? Compare common scheduling algorithms.

CPU scheduling selects which ready process or thread runs next.

AlgorithmKey characteristicTrade-off
FCFSRuns tasks in arrival orderSimple, but a long task can delay every short task.
SJF/SRTFChooses the shortest job or remaining timeGood average waiting time, but requires duration estimates and may starve long jobs.
Round RobinGives each task a fixed time quantumResponsive and fair; a tiny quantum creates excessive context switches.
PriorityRuns the highest-priority task firstImportant tasks respond quickly, but low-priority tasks may starve.

Aging gradually raises the priority of waiting tasks to prevent starvation.

Q6. What is a race condition, and how can it be prevented?

A race condition occurs when multiple threads or processes access shared mutable state concurrently and the result depends on their timing. For example, two threads performing a non-atomic read-modify-write increment can overwrite one another's updates.

Prevent it using mutexes/locks, semaphores, atomic operations, monitors, immutable data, message passing, or by eliminating shared state. Keep critical sections small and always acquire locks in a consistent order.

Q7. What is the difference between a mutex and a semaphore?

A mutex provides mutual exclusion: one owner locks it, enters a critical section, and must unlock it. A semaphore maintains a counter; a thread decrements the counter to acquire a permit and increments it to release one.

A binary semaphore can resemble a mutex, while a counting semaphore is useful for limiting access to a pool of resources—for example, allowing at most ten concurrent database operations.

Q8. What is deadlock, and what four conditions are required for it?

A deadlock is a state in which tasks wait forever for resources held by one another. All four Coffman conditions must exist:

  1. Mutual exclusion: a resource can be held by only one task.
  2. Hold and wait: a task holds one resource while requesting another.
  3. No preemption: resources cannot be forcibly taken away.
  4. Circular wait: a cycle of tasks exists, each waiting for the next.

Deadlocks can be handled through prevention, avoidance such as Banker's algorithm, detection and recovery, or practical measures such as consistent lock ordering and timeouts.

Q9. What is virtual memory, and how does paging work?

Virtual memory gives each process the illusion of a large, private, contiguous address space. The OS and memory-management unit translate virtual addresses into physical RAM addresses.

With paging, virtual memory is divided into fixed-size pages and physical memory into equal-size frames. Page tables store the mappings, while the TLB caches recent translations. Pages that are not currently required may stay on disk and be loaded into RAM on demand.

Q10. What is a page fault, and what is thrashing?

A page fault occurs when a process accesses a virtual page that is not currently mapped into physical memory. The OS verifies the access, loads the page from disk if necessary, updates the page table, and resumes the instruction. An invalid access instead causes an error such as a segmentation fault.

Thrashing happens when memory pressure makes the system spend most of its time repeatedly swapping pages rather than executing useful work. Reducing active workloads, adding memory, or improving locality can help.

Q11. What is the difference between user mode and kernel mode?

User mode restricts applications from directly accessing protected memory, hardware, or privileged CPU instructions. Kernel mode gives the operating-system kernel unrestricted access so it can manage hardware and system resources.

An application requests privileged work through a system call. The CPU switches to kernel mode, the kernel validates and performs the operation, and control then returns to user mode. This separation prevents an ordinary application failure from directly corrupting the whole system.

Q12. What is inter-process communication (IPC)?

IPC is the set of mechanisms processes use to exchange data and coordinate work. Common options include pipes, named pipes, message queues, shared memory, sockets, signals, and memory-mapped files.

Shared memory is fast because processes can access the same region directly, but it needs synchronization. Message passing and sockets provide stronger separation and are easier to distribute across machines, though serialization and data copying add overhead.
