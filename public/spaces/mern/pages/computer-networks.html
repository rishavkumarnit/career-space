Computer Networks Fundamentals

Q1. What is a computer network?

A computer network is a group of connected devices that exchange data and share resources using agreed protocols. Networks may be classified by scope: a LAN covers a limited area, a MAN spans a city or campus, and a WAN connects geographically distant networks. The Internet is the largest WAN.

Q4. How does DNS resolve a domain name?

The client checks browser, OS, and local caches, then asks a recursive resolver. On a cache miss, the resolver follows referrals from a root server to the relevant TLD server and then the domain's authoritative server. It returns the record—commonly an A or AAAA address—and caches it for its TTL.

Useful records: CNAME aliases a name, MX routes email, TXT stores verification/policy text, and NS identifies authoritative name servers.

Q5. What are an IP address, subnet mask, and default gateway?

An IP address identifies a network interface. The subnet mask or CIDR prefix separates the network portion from the host portion; for example, 192.168.1.20/24 belongs to network 192.168.1.0. A host sends same-subnet traffic directly, but sends off-subnet traffic to its default gateway, normally a router.

IPv4 uses 32-bit addresses; IPv6 uses 128-bit addresses and provides a vastly larger address space.

Q6. What is subnetting, and why is it useful?

Subnetting divides an IP network into smaller networks by extending its prefix. It conserves addresses, reduces broadcast domains, improves organization, and enables security boundaries. Splitting 192.168.1.0/24 into four equal subnets produces four /26 networks, each with 64 total IPv4 addresses (normally 62 usable host addresses).

Q7. What do ARP and DHCP do?

ARP resolves an IPv4 address to a MAC address on the local network so an Ethernet frame can reach the next hop. DHCP automatically supplies IP configuration using DORA: Discover, Offer, Request, Acknowledge. A lease commonly includes an IP address, subnet mask, gateway, DNS servers, and expiry time.

Q9. What are NAT and PAT?

NAT translates addresses between networks, commonly mapping private IPv4 addresses to public addresses. PAT (NAT overload) also translates port numbers so many internal devices can share one public IP. NAT conserves IPv4 addresses, but it is not a substitute for a firewall.

Q10. What happens when you enter an HTTPS URL in a browser?
  1. The browser parses the URL and checks caches and policies.
  2. DNS resolves the hostname to an IP address.
  3. The client reaches the server, normally using TCP plus TLS, or QUIC for HTTP/3.
  4. During TLS negotiation, the certificate is validated and session keys are established.
  5. The browser sends the HTTP request; proxies, load balancers, and application servers may handle it.
  6. The response returns, and the browser parses HTML, fetches dependencies, lays out, and renders the page.
Q11. What is the difference between HTTP and HTTPS?

HTTPS is HTTP carried through TLS. TLS provides confidentiality through encryption, integrity against undetected modification, and authentication through certificates. HTTPS does not make an application itself secure; authorization, input validation, secure cookies, and other controls are still required.

Q12. How would you troubleshoot a website that is slow or unreachable?
  1. Define scope: one user, one region, one endpoint, or everyone.
  2. Check local connectivity, proxy/VPN settings, and whether the hostname resolves correctly.
  3. Use ping where permitted, traceroute/tracert, nslookup/dig, and curl -v to isolate DNS, routing, TCP/TLS, and HTTP.
  4. Check status codes, timing breakdowns, packet loss, latency, firewall rules, load balancer health, and server metrics/logs.
  5. Compare a known-good client or region and correlate the failure with deployments or configuration changes.

Do not assume an application bug until the failing layer is identified.
